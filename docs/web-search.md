# Поиск DuckDuckGo и чтение веб-страниц

OpenClaw получает два инструмента: `web_search` для вопросов и `web_fetch` для чтения
выбранных публичных HTTP(S)-страниц. Поиск явно направлен в `duckduckgo`, поэтому он
не переключается на нативный поиск модели или другой поисковый API. Новый API-ключ
и новый контейнер не нужны; обычные расходы на модель и контекст сохраняются.

DuckDuckGo-плагин использует экспериментальную неофициальную HTML-интеграцию,
а не официальный поисковый API. Возможны CAPTCHA, блокировки и изменения разметки.
Плагин не обходит их: ассистент должен сообщить, что поиск не удался.

Конфигурация сверена с официальными документацией и схемой OpenClaw `v2026.10.9`.
Наличие файла патча в репозитории само по себе не устанавливает плагин и не меняет VPS.
При подготовке этих изменений приложение, Docker-контейнеры и тесты не запускались,
запросы в DuckDuckGo и рабочие интеграции не выполнялись.

## Подключение на существующем VPS

Команды ниже предназначены владельцу для последующего применения в каталоге проекта.
Сначала перенесите обновлённые файлы проекта на сервер. Не перезаписывайте существующий
`.env`: новых переменных для самого DuckDuckGo нет. Если переходите на текущую конфигурацию
со старой версии, сначала согласуйте OpenRouter, окружение шлюза и mount навыка по
[инструкции README](../README.md#обновление-существующего-vps).

1. Установите плагин **до** применения патча с `provider: "duckduckgo"`:

   ```bash
   scripts/openclaw.sh plugins install @openclaw/duckduckgo-plugin --pin
   scripts/openclaw.sh plugins enable duckduckgo
   ```

   `--pin` сохраняет точную разрешённую npm-версию в записи установки. Это не обещает
   совместимость произвольной версии плагина со старым образом OpenClaw. Сверьте версию
   шлюза и сообщения установки; при ошибке установки не переходите к применению патча.
   Отдельное включение также снимает сохранённый ранее `enabled: false`.

2. Пересоздайте шлюз для актуального окружения и read-only mount навыка, затем примените патч.
   `TELEGRAM_CHAT_ID` и `TIMEZONE` берутся из окружения, подстановка через `sed` не нужна:

   ```bash
   docker compose up -d --force-recreate openclaw-gateway
   scripts/openclaw.sh config patch --stdin < openclaw/openclaw.patch.json5
   scripts/openclaw.sh config validate
   ```

   Патч сохраняет ограничения файлов и команд, добавляет разрешения `web_search` и
   `web_fetch`, включает плагин `duckduckgo` и выбирает его поисковым провайдером.
   Не заменяйте `plugins.allow` списком из одного DuckDuckGo: этим можно отключить другие
   плагины. Если на VPS уже есть отдельный ограничивающий список плагинов или запрет
   `duckduckgo`, согласуйте его с новой установкой, сохраняя текущие Telegram и модель.

3. Проверьте подключённый навык и начните новую сессию сообщением `/new` боту:

   ```bash
   scripts/openclaw.sh skills info secretary
   ```

   Ожидаемый путь — `/home/node/.openclaw/workspace/skills/secretary/SKILL.md`: каталог
   приходит из `openclaw/skills/secretary` через read-only mount внутри workspace. `extraDirs`
   и копирование не нужны. Старая копия secretary на диске скрывается mount, удалять её не нужно.
   Обычный `restart` не подключает новый mount. Установленные плагины и их состояние находятся в постоянном `data/openclaw`, который
   смонтирован как `/home/node/.openclaw`. Пересоздание контейнера не требует повторной
   установки при сохранении этого каталога. Vault в gateway не монтируется.
   Установка/включение и применение конфигурации могут обновить работающий шлюз;
   это эксплуатационные действия, они не выполняются при статической проверке проекта.

## Настройки и объём выдачи

| Параметр | Значение | Смысл |
|---|---|---|
| `tools.alsoAllow` | `read`, `web_search`, `web_fetch` | Навык и два веб-инструмента поверх `messaging` |
| `tools.web.search.provider` | `duckduckgo` | Явный выбор поискового провайдера |
| `tools.web.search.maxResults` | `5` | Число результатов по умолчанию; не жёсткий лимит запросов или всех результатов |
| `tools.web.search.timeoutSeconds` | `20` | Таймаут поиска |
| `tools.web.search.cacheTtlMinutes` | `15` | Кэш повторных поисковых запросов |
| `tools.web.fetch.maxChars` | `6000` | Обычный размер прочитанного фрагмента страницы |
| `tools.web.fetch.maxCharsCap` | `8000` | Жёсткий предел выдачи страницы при переопределении `maxChars` |
| `tools.web.fetch.maxResponseBytes` | `250000` | Ограничение скачиваемого тела перед разбором |
| `tools.web.fetch.timeoutSeconds` | `20` | Таймаут чтения страницы |
| `tools.web.fetch.maxRedirects` | `3` | Предел перенаправлений |
| `tools.web.fetch.ssrfPolicy.dangerouslyAllowPrivateNetwork` | `false` | Без широкого доступа к частным сетям |

Плагин допускает `count` от 1 до 10: значение `maxResults: 5` задаёт умолчание.
Навык просит начинать с одного запроса, максимум пяти результатов и чтения одной–трёх
страниц. Это инструкции выбора объёма работы, а не гарантированный денежный лимит за
диалог. Жёсткий предел `maxCharsCap` относится к странице, не ко всему контексту модели;
служебные метаданные также занимают место. Для контроля контекста используйте
`/context detail` и `/usage tokens` в OpenClaw.

`web_fetch` выполняет HTTP-запрос и извлекает текст, не исполняя JavaScript. Страницы с
логином, защитой от ботов и динамическим интерфейсом могут быть недоступны. Если Readability
не может извлечь страницу и отдельный fetch-провайдер не настроен, чтение может завершиться
ошибкой. Установка браузера и платного резервного провайдера в эту настройку не входит.

## Поведение и безопасность

- Ассистент ищет по прямой просьбе и для актуальных сведений, сообщает источники и отделяет
  найденные факты от собственных выводов. Для обычного сохранения заметки поиск не нужен.
- Поисковый запрос передаётся DuckDuckGo; выбранный URL получает HTTP-запрос. Не включайте
  в них содержимое личных заметок, календаря, секреты и приватные расшифровки голосовых.
  Если без приватного текста вопрос не решить, сначала требуется согласие владельца.
- Сайты и поисковые результаты — недоверенные данные. Их текст не разрешает отправлять
  сообщения, раскрывать файлы, изменять календарь или заметки. Существующие ограничения
  `tools.fs.workspaceOnly`, `deny` и `elevated.enabled: false` сохранены.
- Не разрешайте `localhost`, контейнерные адреса, WebDAV, cloud metadata и частные сети
  для обхода ошибок чтения сайтов. Не добавляйте глобальные заголовки с `AUTH_TOKEN` или
  другими секретами в `tools.web.fetch.headers`: адрес страницы выбирает модель.
- Существующие прокси-переменные Compose сохраняются. Строгий `web_fetch` по умолчанию
  применяет собственные сетевые проверки; простой факт наличия `HTTPS_PROXY` не доказывает,
  что все веб-инструменты идут через него. Для закрытого выхода через доверенный прокси
  нужна отдельная настройка по официальной документации, без отключения защиты частных сетей.

## Проверка после применения владельцем

На VPS можно посмотреть `scripts/openclaw.sh plugins list` и выполнить
`scripts/openclaw.sh security audit`, затем открыть новый диалог с ботом и попросить:
«Найди актуальную информацию об …, укажи источники» или «Прочитай эту публичную статью …».
Проверяйте фактические вызовы инструментов и ссылки; наличия параметров в конфигурации
недостаточно для подтверждения рабочего доступа в интернет. Лимиты контекста видны через
`/context detail`, расход — через `/usage tokens`.

Если поиск недоступен, сначала проверьте установленный/включённый плагин, выбранный
провайдер, ограничения инструментов и сетевой доступ VPS. CAPTCHA может возникать и при
корректной настройке. Не запускайте бесконечные повторы и не меняйте провайдера молча.
